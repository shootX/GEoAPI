# CarAPI — დიზაინის პროექტი

ეს დოკუმენტი არის ერთადერთი ბრიფი. მისი მიხედვით უნდა გაკეთდეს პროდუქტის სრული ვიზუალური დიზაინი: ყოველი გვერდი, ყოველი ღილაკი, ყოველი მდგომარეობა, სამ სიგანეზე. ტექსტი ქართულია. ახალი ფუნქცია არ იგონება.

## ბრძანება მოდელისთვის

შენ ხარ პროდუქტის დიზაინერი. წაიკითხე ეს ფაილი ბოლომდე და დააბრუნე სტატიკური HTML პროტოტიპი ერთ საქაღალდეში `design/`.

შედეგი:

- `design/tokens.css` — ქვემოთ ჩაწერილი ტოკენები, ცვლილების გარეშე.
- `design/components.css` და `design/components.html` — ყოველი კომპონენტი ყოველ მდგომარეობაში.
- თითო ეკრანი ცალკე HTML ფაილია, სახელი ცხრილის მიხედვით.
- თითო ეკრანზე სამი ჩარჩო: `data-frame="desktop"` 1440px, `data-frame="tablet"` 768px, `data-frame="mobile"` 390px. შიშველი გვერდები (`closed`, `preview`) ერთ ჩარჩოზე საკმარისია, მაგრამ ტექსტი არ იჭრება.
- მდგომარეობა ცალკე ფაილია, თუ ქვემოთ წერია „ცალკე კადრი“. სხვა შემთხვევაში იმავე ფაილში, `hidden` სექციით, სათაურით.
- ღილაკის წარწერა ზუსტად ისაა, რაც ამ ფაილში წერია. ტექსტი არ შეამოკლო და არ თარგმნო.
- ინტერაქცია მხოლოდ ვიზუალურია: მენიუ იხსნება, თემა იცვლება, კოპირება წერს „ტექსტი დაკოპირებულია“. სერვერს არ უკავშირდება.
- ბოლოს `design/index.html`: ყველა ეკრანის ბმული, დაჯგუფებული გარსის მიხედვით.

არ დაასრულო ნაწილობრივი ნაკრებით. თუ ეკრანი ამ ფაილშია, ის პროტოტიპშიც უნდა იყოს.

## 1. პროდუქტი

CarAPI დეველოპერის SaaS-ია. მომხმარებელი იღებს ავტომობილის კატალოგს ორი გზით:

1. სერვერული REST: `GET /api/v1`, საიდუმლო გასაღები `Authorization: Bearer carapi_sk_…`.
2. ჩასასმელი ვიჯეტი `<carapi-filter>`, საჯარო გასაღები `carapi_pk_…`.

კატალოგის ჯაჭვი: ბრენდი → მოდელი → თაობა. მოდიფიკაცია და მისი დეტალი სერვერულ API-შია. ვიჯეტის ჯაჭვი სხვაა: ბრენდი → მოდელი → გამოშვების წელი → ძარის ტიპი.

ენა `ka`. ოპერატორი შპს „ინოვა ლაბ“. კონტაქტი `info@socialsave.cc`. საიტი `https://car.socialsave.cc`.

ლიმიტი, რომელიც ტექსტად რჩება და ფასი არ არის: 60 მოთხოვნა წუთში და 10 000 წარმატებული მოთხოვნა UTC თვეში, თითო პროექტზე. ვიჯეტი და სერვერული API ერთ მრიცხველს იყენებენ.

### როლები

| როლი | რას ხედავს |
|---|---|
| სტუმარი | მთავარი, დოკუმენტაცია, წესები, კონფიდენციალურობა, შესვლა, რეგისტრაცია, პაროლის აღდგენა |
| მომხმარებელი | `/account` და მხოლოდ საკუთარი პროექტი |
| ადმინი | შესვლის შემდეგ `/admin`. საკუთარი კაბინეტი `/account` ცალკე ბმულით |

## 2. რა არ უნდა გამოჩნდეს

დიზაინში არ დახატო:

- ავტომობილის მაღაზია, განცხადება, VIN, სანომრე ნიშანი, დილერი, ფასი, საბაზრო ღირებულება
- ტარიფის შედარება, გადახდა, ინვოისი, ბარათის ფორმა
- ადმინის გამორთული პუნქტების შიდა ეკრანები. ისინი მხოლოდ მენიუშია, წარწერით „მალე“
- ფოტოს გალერეა. მიმდინარე ვერსია ფოტოს არ გასცემს
- ინგლისური ინტერფეისი, OpenAPI-ის ცალკე საიტი, SDK-ის გვერდი
- ძველი რეგისტრაცია ფიზიკური/იურიდიული პირით და ტელეფონით

ადმინის მენიუში „მალე“ რჩება ეს ექვსი პუნქტი, ბმულის გარეშე: API მოხმარება, API გასაღებები, გამოწერის გეგმები, გამოწერები, გადახდები, აუდიტის ჟურნალი. მათ ქვეშ ერთი წინადადება: „მართვის ფუნქციები დაემატება შემდეგ ეტაპებზე.“

## 3. ერთი კონცეფცია

სახელი: **ნათელი პანელი**.

ვიზუალური რეფერანსი არის მსუბუქი SaaS-პანელი: ტილო რბილია, აპი ზის ერთ მცურავ თეთრ ჩარჩოში დიდი რადიუსით, მარცხნივ წყნარი მენიუ, მარჯვნივ სათაური, გრაფიკი და 2×2 მეტრიკის ბარათი, ქვემოთ თხელი ცხრილი. CarAPI ამ განლაგებას იმეორებს, ნაცრისფერი მონოქრომის ნაცვლად თბილი, მხიარული ფერით.

ფერი სამი ნაბიჯია და მეტი არა: ატმის ტილო, მარჯნის აქცენტი, მზის ყვითელი მხოლოდ პატარა მონიშვნაზე და გრაფიკის შევსებაზე. ბარათები ოთხ რბილ ტონად დგას — ატამი, კარაქი, პიტნა, იასამანი — რიცხვი კი მუქი რჩება. მანქანის რეკლამა არ არის. ხაზი თხელია, რიცხვი ტაბულურია, კოდი მონოა.

ორი თემა ერთი სისტემისაა. ღია არის ნაგულისხმევი დიზაინის ჩარჩოებში. მუქი არის იგივე განლაგება თბილ ქლიავის ფონზე, იგივე მარჯნით და მზით. ადმინი, კაბინეტი, საჯარო საიტი და ვიჯეტი ერთ პალიტრას იყენებს. ცალკე „ადმინის სტილი“ არ არსებობს.

## 4. კომპონენტები

ყოველ კომპონენტს აქვს ნაგულისხმევი, hover, focus-visible, disabled. დამატებითი მდგომარეობა ქვემოთ წერია.

### ღილაკი

სიმაღლე 40px, padding 0 16px, radius `--radius`, წონა 600. ერთ ხაზზე. აიქონი 16px, ტექსტის მარცხნივ, ხარვეზი 8px.

| სახეობა | როდის | ვიზუალი |
|---|---|---|
| ძირითადი | გვერდის ერთი მთავარი ქმედება | ფონი `--lime`, ტექსტი `--lime-ink`, საზღვარი `#E25A28` |
| მეორე | დანარჩენი ქმედება | გამჭვირვალე, საზღვარი `--line-2` |
| ტექსტური | ნავიგაცია, რომელიც ღილაკად არ უნდა ყვიროდეს | ტექსტი `--ink-2`, საზღვრის გარეშე |
| საფრთხე | მხოლოდ დადასტურების მოდალში | ფონი `--danger`, ტექსტი თეთრი |

Disabled: opacity .55, კურსორი `not-allowed`. დატვირთვა: წარწერა იცვლება და ღილაკი disabled ხდება. ორი ძირითადი ღილაკი ერთ ბლოკში არ დგას.

### ველი

სიმაღლე 48px, სრული სიგანე, საზღვარი `--line-2`, ფონი `--panel`, radius `--radius`. ლეიბლი ზემოთ, 14px `--ink-2`. მინიშნება ქვემოთ, 12px `--mute`. შეცდომა: საზღვარი `--danger`, ტექსტი `--danger`, ლეიბლთან `aria-invalid`. წარმატება არ იწერება ველის შიგნით.

პაროლი: მარჯვნივ 32px ღილაკი „პაროლის ჩვენება“ / „პაროლის დამალვა“. ახალ პაროლს ქვემოთ ოთხი 3px ზოლი აქვს. შევსებული ზოლი `--lime` / ღიაზე `--olive`.

textarea მინიმუმ 96px. select იგივე სიმაღლისაა, რაც input. checkbox 16px, ტექსტი მარჯვნივ, ბმული ხაზგასმული.

ახსნა: საიდუმლო გასაღები სრულად მხოლოდ შექმნისას ჩანს. გაუქმების შემდეგ ახალი მოთხოვნა აღარ ავტორიზდება.

რიგები:

- ვიჯეტი: სახელი „ვიჯეტი საიტზე“, pill „საჯარო API გასაღები“, ნიღაბი `carapi_pk_…` შუაში, კოპირება სრულ მნიშვნელობას კოპირებს, ვადა „—“, სტატუსი აქტიური ან გამორთული. გაუქმების ღილაკი არ აქვს.

ჩასმა. ახსნა რომ public-key უკვე ამ პროექტისაა და HTML-ში ჩვენება დასაშვებია. readonly კოდი, მეორე „კოდის კოპირება“, ბმული „წინასწარი ნახვა“. მინიშნება: წინასწარი ნახვა იმავე თვიურ ლიმიტს ხარჯავს.
