# ჩასასმელი ფილტრი

production-ში სამივე დროშა ჩართულია. მონაცემები იხსნება, როცა ვიჯეტი, კატალოგი და პლატფორმა ერთად ჩართულია. ისტორიულად, ჩართვამდე, გამორთული მდგომარეობა 404-ს აბრუნებდა.

საჯარო გასაღები `carapi_pk_...` პროექტის იდენტიფიკატორია. საიტის სტუმარი მას HTML-ში ხედავს. ეს საიდუმლო არ არის და Origin-ის შემოწმება ბრაუზერის შეზღუდვაა, არა ავთენტიფიკაცია: სხვა HTTP კლიენტს Origin-ის გაყალბება შეუძლია. სერვერული `carapi_sk_` გასაღები ჩასასმელ კოდში არასოდეს ხვდება.

## ჩასმა

```html
<script src="https://geoapi.ge/widget/v1/carapi-filter.js"></script>
<carapi-filter public-key="carapi_pk_საჯარო_გასაღები"></carapi-filter>
```

თითო ველი საძიებოა. დაწკაპებისას სრული სია იხსნება, ორი სიმბოლოს შემდეგ კი სია ფილტრდება. ქართულ განლაგებაზე აკრეფილი ტექსტიც ემთხვევა ლათინურ სახელს, მაგალითად „ტოყ“ პოულობს Toyota-ს. მუშაობს ისრებით, Enter-ით და Escape-ით. ძებნა ბრაუზერში ხდება უკვე ჩატვირთულ სიაში და დამატებით მოთხოვნას არ აგზავნის.

სკრიპტი API მისამართს თავისი `src`-იდან იღებს, არა მასპინძელი საიტის დომენიდან. `show-photos` ნაგულისხმევად გამორთულია. `true`-ზეც ფოტო არ მოდის, რადგან ფოტოს სერვისი ამ ვერსიაში არ არის. `/getImage` არ გამოიყენება.

დაშვებული origin-ები ცალკე სიაა. `website_url` მხოლოდ აღწერაა. უნდა ემთხვეოდეს სრული origin: scheme, hostname და port. Wildcard არ მიიღება. HTTP მხოლოდ `localhost` ან `127.0.0.1`-ისთვის, თუ მას პატრონი აშკარად დაამატებს. ცარიელი ან `null` Origin უარყოფილია.

მონაცემები:

```http
POST /widget/v1/{publicKey}/brands
POST /widget/v1/{publicKey}/brands/{slug}/models
POST /widget/v1/{publicKey}/models/{id}/generations
```

სხეული JSON-ია: `page`, `per_page`. POST მონაცემს არ ცვლის. `fetch` იყენებს `credentials: "omit"`. პასუხი `Cache-Control: no-store`-ითაა, რომ საერთო კეშმა გაუქმებას და აღრიცხვას არ აუვლოს გვერდი.

ვიჯეტი და სერვერული API ერთი პროექტის წუთისა და თვის კვოტას ხარჯავს. წარმატებული გვერდი ერთი ერთეულია. კაბინეტში ვიჯეტის მარშრუტი ჩანს როგორც `widget:brands`, `widget:models`, `widget:generations`. Preview-ის მოთხოვნებიც ითვლება. Preview-ის origin პატრონმა თვითონ უნდა დაამატოს.

## მოვლენა

```html
<carapi-filter public-key="carapi_pk_საჯარო_გასაღები"></carapi-filter>
<script>
  document.querySelector('carapi-filter').addEventListener('carapi:change', function (event) {
    var pick = event.detail;
    // pick.brand_id, pick.model_id, pick.generation_id სტრიქონია ან null
    // pick.modification_id ამ ვერსიაში null-ია
  });
</script>
```

მოვლენას აქვს `bubbles` და `composed`. ფილტრი კლიენტის განცხადებებს თვითონ არ ეძებს. კლიენტი ID-ებით ფილტრავს საკუთარ მონაცემებს. სხვადასხვა ID არ ერთიანდება. თაობის არმქონე მოდელი ჩანს და მაინც გადაეცემა; ტექსტია „ამ მოდელისთვის თაობები ჯერ არ არის დამატებული“.

შეცდომები: 403 origin ან გამორთული ვიჯეტი, 429 ლიმიტი `Retry-After`-ით, 503 სერვისი. ვიჯეტი უსასრულოდ თავიდან არ ცდილობს.

ბრაუზერის შემოწმება: Playwright Chromium 140.0.7339.16, იგივე სერვერზე, სადაც სატესტო PHPა. ბრძანება: `tests/browser/run.sh`. 2026-09-25-ს გავიდა same-origin preview, სხვა პორტის origin, pagination, ორი ვიჯეტი, სწრაფი გადართვა, ცარიელი თაობა, რეალური 429 და გასაღების გამოცვლა. ქსელის ჩავარდნა Playwright-ის `route.abort`-ითაც შემოწმდა. რეალური backend-ის 503, როცა კატალოგის პორტი მიუწვდომელია, ცალკე Playwright-ით დადასტურდა: ბრაუზერმა წაიკითხა 503, ვიჯეტმა აჩვენა შეცდომა და კვოტა არ გაიზარდა. ორი PHP პროცესით სერვერულმა და ვიჯეტის მოთხოვნამ ერთად ერთი 200 და ერთი 429 მიიღო, მრიცხველი 1-ით გაიზარდა.
