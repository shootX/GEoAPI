# პროექტის აუდიტი

მიმდინარე მდგომარეობა, 2026-09-26: საჯარო გვერდი CarAPI-ს აღწერს. კატალოგი, პროექტები და მოხმარება რეალური ნაკადიდან მოდის, როცა დროშები ჩართულია. Production-ის სამივე დროშა ჩართულია. საჯარო რეგისტრაცია, API და ფილტრი მუშაობს. ფოტოები, მოდიფიკაციები და გადახდა არ შედის. ანგარიშის მონაცემების ავტომატური სარეზერვო ასლი გამართული არ არის. მფლობელმა დაადასტურა, რომ CarAPI-ის სერვერი გერმანიაშია და ჰოსტინგის პროვაიდერია Contabo. პროვაიდერის ზუსტი იურიდიული დასახელება და ხელშეკრულება მოწოდებული არ არის. სხვა მომსახურებების მდებარეობა და საერთაშორისო გადაცემის სამართლებრივი საფუძველი ამით არ დასტურდება. შრიფტი ადგილობრივი ფაილია. `/privacy` აღწერს დამუშავების მიზნებს და უფლებებს; მონაცემთა დაცვის ოფიცერი დანიშნული არ არის. ქვემოთ თავდაპირველი აუდიტის ტექსტი ისტორიულია.

თარიღი: 2026-09-25.  
საჯარო მისამართი: https://car.socialsave.cc/  
ეს დოკუმენტი მხოლოდ აუდიტია. აპლიკაციის კოდი, დამოკიდებულებები და ბაზის მონაცემები არ შეცვლილა.

ნიშნები:

- **ფაქტი** — კოდით, კონფიგურაციით ან წაკითხვის მოთხოვნით დადასტურდა.
- **ვარაუდი** — ფაქტებიდან გამომდინარეობს, მაგრამ ცალკე არ დადასტურდა.
- **შეუმოწმებელი** — ამ ეტაპზე არ გაშვებულა ან წყარო ამ რეპოზიტორიაში არ არის.

## რეალურად მოქმედი ფუნქციები

ქვემოთ „მოქმედი“ ნიშნავს: კოდის გზა სრულდება და გარე ეფექტი დისკზე ჩანს. ამ აუდიტში HTTP მოთხოვნა არ გაგზავნილა, რადგან მთავარი გვერდი ხსნის SQLite-ს და პირველივე გამოძახებაზე ქმნის ცხრილებს (`src/Auth/Database.php` → `migrate()`).

1. **`GET /getImage` — ფაქტი, რომ კოდი და კეში არსებობს.**  
   `public/index.php` იღებს `make`, `model` (ან `modelFamily`), `year` (ან `modelYear`), `format=json`. CORS ღიაა.  
   `src/Service.php` ჯერ კითხულობს `cache/`, შემდეგ `DromResolver`-ს, სურათს ერთხელ იწერს და ინახავს.  
   `cache/img/`-ში 15 ფაილია, `cache/meta/`-ში 2 ჩანაწერი. მაგალითი `cache/meta/6893f8bd11dafcac7931b7e4cd7947d893eb7bfc.json`: Subaru XV, პერიოდი `09.2011 - 06.2016`, თაობა `1 поколение`. ლიცენზიის ველი ცარიელია, `source` არის `carapi`.  
   **შეუმოწმებელი:** ახლა გარე წყარო პასუხობს თუ არა. 15 სურათიდან მხოლოდ 2-ს აქვს meta — დანარჩენი ობლებია თუ ძველი კეში, არ გარკვეულა.

2. **რეგისტრაცია, შესვლა, სესია, პროფილი — ფაქტი კოდში, დისკზე მომხმარებელი არ არის.**  
   მარშრუტები: `/login`, `/register`, `/logout`, `/account`, `/auth/me` (`src/Auth/Router.php`).  
   CSRF, სესიის რეგენერაცია, 8 მცდელობა / 15 წუთი (`src/Auth/SessionAuth.php`).  
   პაროლი `password_hash`. ფიზიკურ პირს სჭირდება 11-ნიშნა პირადი ნომერი, იურიდიულს 9-ნიშნა საიდენტიფიკაციო კოდი (`src/Auth/Registrar.php`, ველები `src/Auth/View.php`).  
   `data/` ცარიელია, `carapi.sqlite` არ არის. **შეუმოწმებელი:** ცოცხალი ფორმის პასუხი.

3. **პანელის ძებნა და ისტორია — ფაქტი კოდში.**  
   `/account` იძახებს იმავე `Service::get()`-ს და წერს SQLite `lookups` (ბოლო 50). ბაზის ფაილი არ არსებობს, ამიტომ შენახული ისტორია არ არის.

4. **ლენდინგი `/` და `/docs` — ფაქტი, რომ ერთი HTML გვერდია** `public/index.php` ფუნქციაში `carapi_landing()`. ცალკე დოკუმენტაციის აპი არ არის.

## ბაზის არსებული სტრუქტურა და კავშირები

### სად დევს

- **ფაქტი:** PostgreSQL ბაზა `carbase` იმავე სერვერზეა. ამ PHP პროექტს მასთან კავშირის კოდი, DSN და მიგრაცია არ აქვს.
- **ფაქტი:** სქემის SQL ამ რეპოზიტორიაში არ არის.
- **ვარაუდი:** კატალოგი შეგროვებულია გარე ავტოკატალოგიდან. ამას ამყარებს ველები `drom_firm_id`, `drom_generation_id`, `drom_complectation_id` და პერიოდის ტექსტი `MM.YYYY - н.в.`. შემგროვებელი პროგრამა ამ რეპოში არ არის. **შეუმოწმებელი:** რომელი პროცესი წერს `carbase`-ს.

შემოწმება იყო მხოლოდ წაკითხვა: სვეტები, გასაღებები, ინდექსები, `count(*)` და მცირე ნიმუში. სრული სკანირება გარე მსგავსებაზე არ გაშვებულა.

### კავშირი

```
brands (313)
  └─ models.brand_id → brands.id (4704)
       ├─ model_markets.model_id → models.id (3070)
       ├─ generations.model_id → models.id (2158)
       │    ├─ generation_photos.generation_id → generations.id (0)
       │    └─ modifications.generation_id → generations.id (0, nullable)
       └─ modifications.model_id → models.id (0)
            ├─ modification_specs.modification_id → modifications.id (0)

```

ყველა ეს FOREIGN KEY დადასტურდა `pg_constraint`-ით. ობოლი `models` ან `generations` ჩანაწერი 0-ია, რადგან FK ჩართულია.

### ცხრილები, რომლებსაც კატალოგი იყენებს

**`brands`:** `id`, `drom_firm_id` UNIQUE, `slug` UNIQUE, `name`, `synonyms` jsonb, `is_lcv_or_commercial`, `logo_url_light`, `logo_url_dark`, `source_url`, `scraped_at`.  
ლოგოს ორივე URL ცარიელია 313/313-ზე. სინონიმი არ აქვს 55 ბრენდს.

**`models`:** `id`, `brand_id`, `slug`, `name`, `source_url`, `rating_value`, `rating_count`, `scraped_at`.  
UNIQUE `(brand_id, slug)`.

**`generations`:** `id`, `model_id`, `drom_generation_id`, `slug`, `name`, `chassis_code`, `body_type`, `year_start`, `year_end`, `period_text`, `market`, `steering_wheel`, `photo_urls` jsonb, `source_url`, `scraped_at`.  
UNIQUE `(model_id, drom_generation_id)`.

**`model_markets`:** `model_id`, `market_slug`, `source_url`. UNIQUE `(model_id, market_slug)`.  
ბაზრები: `russia` 835, `europe` 728, `china` 468, `usa` 455, `japan` 402, `uae` 95, `cis` 87.

### ცარიელი, მომავალი ცხრილები

`modifications`, `modification_specs`, `modification_equipment`, `photos`, `generation_photos` — სქემა არის, ჩანაწერი 0. ეს ემთხვევა გეგმას, რომ მოდიფიკაციები და ფოტოები მოგვიანებით დაემატება.

`photos` ინახავს slug-ებს (`brand_slug`, `model_slug`, `generation_slug`), FK კატალოგის `id`-ზე არ აქვს. `original_url`-ზე ორი UNIQUE ინდექსია: `photos_original_url_key` და `photos_original_url_uidx`.

### წლები და ნიმუში

- `year_start` / `year_end` არის `integer` (მხოლოდ წელი). თვე მხოლოდ `period_text`-შია.
- 2158/2158 `period_text` იწყება `MM.YYYY` ფორმით.
- 1703 დახურული დიაპაზონია `MM.YYYY - MM.YYYY`.
- 455-ს `year_end` ცარიელი აქვს და ტექსტი მთავრდება `н.в.` ნიმუში: `11.2025 - н.в.` → `year_start` 2025.
- დიაპაზონი: `year_start` 1933–2026, `year_end` 1939–2026. `year_end < year_start` არის 0. 1880–2035-ს გარეთ წელი არ ჩანს.

ტესტები იზოლირებულ ბაზაზე გავიდა: `tests/projects_api_keys_test.php`, `tests/platform_auth_test.php`, `tests/catalog_api_test.php`. სამუშაო `carbase`-ში სატესტო პროექტი და გასაღები არ ჩაწერილა.

## ელფოსტა და პაროლის აღდგენა (2026-09-25)

დადასტურება და პაროლის აღდგენა აგებულია (`docs/EMAIL_AND_PASSWORD_RESET.md`). ტოკენი ბაზაში მხოლოდ ჰეშით ინახება. ტესტი fake transport-ით გავიდა. რეალური SMTP არ შემოწმებულა, რადგან ჰოსტი, მომხმარებელი და პაროლი არ არის მოცემული. production კვლავ გამორთულია.

## ლიმიტები და მოხმარება (2026-09-25)

კატალოგის წარმატებულ პასუხს აქვს წუთის ლიმიტი, თვიური კვოტა და კაბინეტის სტატისტიკა. დეტალები: `docs/USAGE_AND_LIMITS.md`. production კვლავ გამორთულია.

## შემდეგი ერთი დავალება

ჩასასმელი ფილტრი დაემატა (`docs/WIDGET_INTEGRATION.md`). ცალკე PHP-FPM და უსაფრთხო access log დანერგილია (`docs/DEPLOYMENT.md`). production კვლავ გამორთულია. რჩება SMTP-ის რეალური პარამეტრები და პროქსის ნარჩენი შეზღუდვა: nginx და სხვა საიტების PHP კვლავ `www` მომხმარებელია.
